# Useful Knowledge
- A robots.txt file is a text file on a website's root directory that gives instructions to web crawlers (like search engine bots) on which pages or sections of the site they should or should not crawl
- An sitemap.xml is a file that lists all the URLs on a website to help search engines efficiently crawl, find, and index its content. It acts like a roadmap, making it easier for search engine crawlers to discover pages
- GET and POST are two of the most commonly used HTTP request methods, which define the type of action a client wants to perform on a server.
 - GET Method:
  1. used for retrieving data from the server. It's like asking the server to "get" you a resource.
  2. Less secure for sensitive data as information is exposed in the URL and can be stored in browser history and server logs.
   - `https://site.com/login?user=admin&pass=123`
  3. GET requests can be cached by browsers and proxy servers, improving performance for repeated requests
  
 - POST Method:
  1. used for submitting data to the server to create or update a resource. It's like "posting" new information to the server
  2. More secure for sensitive information, Data is sent in the request body, not visible in the URL
   - `user=admin&pass=123`
  3. POST requests are generally not cached
  
- `/bWAPP/login.php: Cookie PHPSESSID created without the httponly flag`
 1. PHPSESSID is the default session ID cookie used by PHP.
  - When a user visits a PHP website, PHP generates a unique session ID.
  - That ID is stored in a cookie named PHPSESSID
  - The server uses it to identify the user on every request
  - If an attacker steals the victim’s PHPSESSID, they can hijack the session and act as the victim.
 2. HttpOnly flag
  - When HttpOnly is enabled, JavaScript cannot read the cookie
  - HttpOnly = ON → Safer
  - HttpOnly = OFF → Vulnerable to XSS cookie theft

- `+ /bWAPP/test.php?%3CSCRIPT%3Ealert('Vulnerable')%3C%2FSCRIPT%3E=x: OmniHTTPD's test.php is vulnerable to Cross Site Scripting (XSS). See: http://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2002-1455`
 - **Cross-Site Scripting** (XSS) is a web-security vulnerability that allows an attacker to inject malicious JavaScript into a website so that it runs in the browser of other users
  1. **Reflected XSS**: The malicious script is sent in the URL and reflected immediately by the server.
   - payload inside a URL → reflected in search results
   - `http://192.168.1.7/bWAPP/test.php?%3CSCRIPT%3Ealert(%27Tempest%27)%3C%2FSCRIPT%3E=x` 
  2. **Stored XSS**: The malicious script is saved in the server database and shown to everyone who opens that page.
   - Example: a dangerous comment stored permanently.
