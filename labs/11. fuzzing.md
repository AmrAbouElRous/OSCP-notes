## Fuzzing directories
- Directory fuzzing is an automated technique used in web application security to discover hidden files and directories on a web server by sending numerous crafted requests using a predefined list of common or likely names (a "wordlist"). The goal is to identify potentially sensitive or misconfigured resources that are not linked publicly but are still accessible
- `ls -la /usr/share/wordlists/wfuzz`
- `wfuzz` --> Examples: `wfuzz -c -z file,users.txt -z file,pass.txt --sc 200 http://www.site.com/log.asp?user=FUZZ&pass=FUZ2Z`
- `wfuzz -c -z file,/usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt --sc 200 http://192.168.1.7/bWAPP/FUZZ` --hc 404,301,302
 - OutPUT
 
```=====================================================================
ID           Response   Lines    Word       Chars       Payload                                                                                                                                      
=====================================================================

000003127:   200        6 L      20 W       112 Ch      "666"  

```
 - summary : wfuzz used a wordlist trying to get all accessible files or directories inside your url `http://192.168.1.7/bWAPP/`
 - `http://http://192.168.1.7/bWAPP/666`
- 🔥 Fuzzing can only find files whose names are in your wordlist. If the developer uses unusual names or hides files with permissions, fuzzing won’t find them — so yes, they can hide files from fuzzing.
- ❌ What fuzzing CANNOT show
- Fuzzing cannot show:
  - Files blocked by permissions (no response / always 404) for example : `chmod 000`
  - Files protected by server rules (deny all)
  - Files outside webroot
  - Files with weird names not in your wordlist
  - Files behind authentication you didn’t bypass
